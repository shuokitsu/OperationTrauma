## 記述ルール

1. 1ファイル1テーマ。H1 はファイルのタイトル、以下 H2／H3 で分ける。
2. 各ファイルの冒頭にステータス（草案／確定）と最終更新日を書く。
3. 数値パラメータは表にまとめ、単位（秒、マス、バイタル値、回）を必ず書く。**決定した値と例を区別する**：決定値はそのまま書き、決定ではない値には「例」「例（決定ではない）」と明記する。
4. 決まっていないことは **`TBD-ファイル番号-連番`**（例：`TBD-03-3`。連番は 0 埋めしない）で示し、各ファイル末尾の「未決事項」にまとめる。
   - 見直し提案の ID（A1、R1、M1 など）があれば「提案ID」列に併記してよい。**この ID は決定の経緯を _records でたどるための印で、本文の理解には不要**（本文は仕様書の中で完結して書く）。
   - 解決して消した番号や、記録の無い欠番は、各ファイルの未決事項の末尾に「欠番（再利用しない）」として書く。新しい TBD は、そのファイルの既存の最大番号の次から振る。
5. **決定記録に無い規則を補う必要があるときは、決定として書かない。** 推奨案を本文に書き、**【仮案・未確認】** と明記して、対応する TBD を未決事項に置く。ユーザーが確認したら、【仮案・未確認】を外して決定として書き直し、TBD を消す。
6. 用語は [glossary.md](glossary.md) の定義に合わせる。初めて使う箇所で定義するか、glossary への参照を付ける。
7. 画面遷移や手順の図は Mermaid で書く。
8. 仕様（何をするか）と理由（なぜそうするか）を分け、理由は「補足」として書く。
9. 座標は [x, y]（横, 縦）の順で書く（定義は [04_surgery_area.md](04_surgery_area.md) 1.4）。
