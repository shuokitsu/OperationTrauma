## 1. データ形式

- JSON を候補とする（`TBD-07-1`）。
- データの種類は、医療機器データ・病巣データ（種類）・ステージデータ・システムデータ・シナリオデータ・セーブデータの**6種類**（2章以降）。
  - このうち、ゲームの値（回復値・ダメージ値・時間など）を持ち、**上書きの順番（2.4）と係数の対象になる**のは、前の4種類（医療機器・病巣・ステージ・システム）。2.1 の表はこの4種類だけを扱う。
  - シナリオデータ（会話・字幕などのテキスト。7章）と、セーブデータ（プレイヤーの進み具合や記録。8章）は、ゲームの値を持たないので 2.1 の表には入れない。
- 病巣データとステージデータの関係（1ステージ分の完全な例は 5.8）：

```
ステージデータ（1ステージ）
├── ステージ全体の値（開始バイタル、制限時間、開放条件、目標など）
└── ステップ（配列）
    └── 処置データ
        └── 病巣の配置（配列） ──→ 病巣データ（種類）を参照
                                        └── 治療手順（手順の段階）で使う医療機器 ──→ 医療機器データを参照
```

### 1.1 データの分類（プログラム側と内容側）

データを、プログラムと結びついた「プログラム側」と、プログラムを直さずに作れる「内容側」に分ける（決定、2026-10-03）。ステージと会話は、プログラムに依存せず、内容を調整しながら作る想定。

| 分類 | データ | 考え方 |
|---|---|---|
| **プログラム側** | システムデータ、医療機器データ、病巣データ（種類）、セーブデータ | **数値の調整はデータだけで済む**。新しい**仕組み**（新しい機器、今の部品の組み合わせで作れない病巣など）を足すときに、実装の修正が要る。セーブデータの形式はプログラムが決める |
| **内容側** | ステージデータ（トレーニング用ステージを含む）、シナリオデータ（会話）、素材（画像・音） | プログラムが用意した**部品（書き方）の範囲で**自由に作る。設定されたデータに従って動作し、作成・調整に実装の修正は要らない。素材はファイル名で参照し、差し替えだけなら実装の修正は要らない |

プログラム側のデータで、実装の修正が要る変更と要らない変更：

| データ | 実装の修正が要らない変更 | 実装の修正が要る変更 |
|---|---|---|
| システムデータ | 難易度の係数の値 | 係数を掛ける対象を増やす |
| 医療機器データ | ストック数、ダメージ値、判定範囲 | 新しい機器、操作方法の変更 |
| 病巣データ | 回復値、治療手順の並べ替え（今ある機器の組み合わせ） | 新しい仕組み（例：再出血のような時間による変化を新しく作る） |

- 病巣は、**今ある部品の組み合わせなら、データを足すだけで新しい病巣を作れる**ように設計する。病巣の再整理（テーマ3）では、「新しい仕組みが要る病巣」と「組み合わせで作れる病巣」を分けて考える。

内容側のデータを作るための約束：

- **ステージ・会話で使える部品は、本実装の前にすべて決めておく。** 部品の外のことをしたい場合は実装の修正が要る。まだ決まっていない部品：病巣の出現条件（`TBD-07-2`）、複数病巣の同時多発（`TBD-07-9`）、処置内容の分岐・フラグ・クリア後の処理（`TBD-07-5`）、会話の書式（`TBD-07-3`）。[scenario.md](../scenario.md) の特殊な動き（ステージ4の助手への投薬分岐、闇落ち・光落ちのクリアでエンディングなど）も、部品の一覧に入れる。洗い出しはテーマ6「データ・進行」とテーマ8「最初のゴールの中身」で行う。
- **ステージから病巣・医療機器を参照するときは、ID だけを使う。** 病巣の ID を変えたり消したりすると、ステージ側が動かなくなるため。
- **ステージで上書きできる値は、病巣データ側で決めた項目だけにする**（2.4、5.3）。

## 2. データの種類と基本ルール

値をどのデータに持たせるかの基本ルール（[_records/2026-09-25_data_ownership_draft.md](../_records/2026-09-25_data_ownership_draft.md) の R1〜R7 で決定）。

### 2.1 データの種類

値の置き場所として使う4種類のデータ。1章の6種類のうち、シナリオデータとセーブデータはゲームの値を持たないので、ここには含めない（1章）。

| データ | 何を表すか | 考え方 | 例 |
|---|---|---|---|
| 医療機器データ | 道具そのものの性能 | **どの病巣・どのステージでも同じ値**になるもの | ストック数、筆の半径、空振りしたときの結果 |
| 病巣データ（種類） | 病巣の「ひな形」 | **その種類の病巣なら、どこに出ても同じ**になるもの | 切り傷の治療手順、成功時の回復値、SE |
| ステージデータ | その手術の状況 | **その場面だけ**のもの | 開始時のバイタル、どの病巣を・どこに・いつ出すか |
| システムデータ | ゲーム全体の調整用の値 | ステージによらず、ゲーム全体に掛かるもの | 難易度ごとの係数 |

- 病巣は「種類」（病巣データ）と「配置」（ステージデータ）に分けて持つ。同じ種類の病巣を何度も書かずに済むようにするため。

| | 置き場所 | 持つもの |
|---|---|---|
| 病巣の**種類** | 病巣データ | 見た目、SE、判定データの形、治療手順、回復値・ダメージ値、時間による変化 |
| 病巣の**配置** | ステージデータ | どの種類を・どこに（マス座標）・いつ出すか（出現条件）、この配置だけの上書き値 |

```
病巣データ（種類）        ステージデータ（配置）
┌──────────┐      ┌────────────────────┐
│ 切り傷           │ ←── │ 切り傷を [20,10] に、開始時に出す │
│  手順：ゼリー     │ ←── │ 切り傷を [60,30] に、10秒後に出す │
│  回復：3（例）    │      └────────────────────┘
└──────────┘
```

（図の「回復：3」は説明用の例で、決定値ではない。）

### 2.2 操作の結果の分類

操作の結果は、次の4つに分けて扱う。

| 結果 | 意味 | 例 |
|---|---|---|
| 成功 | 治療手順の1段階が完了した | 通過点をすべて通ってメスで切開できた |
| 失敗（NG） | 病巣に対して操作したが、やり方を誤った | メスが猶予幅を外れた、ピンセットで運び先以外に離した、メスで手順と違う病巣を切った |
| 無効 | 操作したが何も起きない（ダメージも無い） | 長い傷をヒールゼリーで覆いきれなかった、血溜まりがあってゼリーが効かない |
| 空振り | 病巣の無い場所を操作した。その機器にとって対象にならない病巣の上での操作も、空振りとして扱う場合がある（[05_instruments.md](05_instruments.md) 2.1・2.2） | 何も無い皮膚をメスで切った、縫う段階ではない病巣を縫合針で縫った |

- 1回の操作の結果は1つ。分類は押した位置で決める（決定、2026-10-03。[05_instruments.md](05_instruments.md) 2.1）。

### 2.3 結果ごとの値の置き場所

| 結果 | 値の置き場所 | 理由 |
|---|---|---|
| 空振り | **医療機器データ** | 病巣が無い場所なので、道具の性質で決まる |
| 成功 | **病巣データ** | どれだけ回復するかは病巣によって違う |
| 失敗 | **病巣データ**（無ければ医療機器データの既定値） | 病巣ごとに重さが違う。ただし毎回書くのは大変なので、機器の既定値を使えるようにする |
| 無効 | 値は持たない | 何も起きないため |

- ヒールゼリーの「塗っている間の回復」は、成功・無効・空振りのどれでも起きる**道具の性質**で、結果の値ではない。医療機器データに持つ（3章）。
- 「手順違い」は、機器ごとに結果が決まる（失敗・無効・空振り扱いのいずれか。[05_instruments.md](05_instruments.md) 2.2）。

### 2.4 上書きの順番

同じ値が複数の場所にあるときは、**より具体的なほうを優先**する。

```
医療機器データの既定値
   ↓ 病巣データに指定があれば上書き
病巣データ（種類）の値
   ↓ ステージの配置に指定があれば上書き
配置ごとの値
   ↓ 最後に係数を掛ける（03_game_rules.md 6章）
実際の値 ＝ 上の値 × ステージ係数 × 難易度係数
```

- 例：メスの失敗ダメージ（値は説明用の例）
  - 医療機器データ（メス）の既定値：2
  - 病巣データ（切開）に指定が無ければ 2 を使う
  - 病巣データ（腫瘍）の「メスで切る段階」で 4 と指定すれば、腫瘍のその段階のときだけ 4 になる
  - ステージの配置で 3 と指定すれば、その配置のときだけ 3 になる（最優先）
- 上書きできない値もある（例：なぞり操作の判定範囲・猶予幅は医療機器データに固定。3章）。
- 薬の限度量は、医療機器データの既定値をステージデータの患者ごとに上書きする（5.2）。
- 係数を掛ける項目と掛け方（時間・間隔を表す値の向きなど）は [03_game_rules.md](03_game_rules.md) 6章に従う。
- どの場所の値を使うかの補足（決定、2026-10-03）：
  - **手順違い**（病巣の手順に無い機器を使った。[05_instruments.md](05_instruments.md) 2.2）のダメージは、その機器の既定値を使う。病巣データの段階ごとの失敗ダメージは「その段階の機器が失敗したとき」だけに使う。
  - **手順の省略**のダメージは、病巣データに持つ（失敗・空振りとは別の値。ミスの数には数えない。[05_instruments.md](05_instruments.md) 2.2）。
  - **運び先**（ピンセット）は病巣データに持つ。配置で上書きできる（上書き値の1つとして、5.3）。

## 4. 病巣データ（種類）

各病巣の種類について、次の情報を持つ。置く位置と出すタイミングはステージデータ（5.3）に持つ。

| 項目 | 内容 | 出典・補足 |
|---|---|---|
| 見た目 | 表示する画像。**処置が進むと見た目が変わる**（例：異物を摘出したら、除去後の傷が見える。決定、2026-10-03、試作 v03 の P76）。手順の段階ごとに見た目（その段階の間の画像）を持ち、治療が終わった後の見た目も持つ（決定、2026-10-09） | [04_surgery_area.md](04_surgery_area.md) 2章 |
| SE | 発生時の音、手順の段階の完了の音、治療の完了の音 | 処置時の音は手順の段階ごとに指定できる（指定が無ければ共通の「段階の完了」音）。医療機器の操作中の音と重ねて鳴らす（[05_instruments.md](05_instruments.md) 2.6） |
| 判定データ | 治療の成否を判定するための形（マス座標 [x, y]。ヒットエリア、またはメス・縫合針で使う通過点のリスト）。形そのものを持ち、置く位置は配置で決める | [04_surgery_area.md](04_surgery_area.md) 2章、[06_lesions.md](06_lesions.md) 3.6。データの座標は、配置の位置を [0, 0] とした**相対座標**（決定、2026-10-03） |
| 治療手順 | 医療機器を使う順番（例：ドレーン → ピンセット → 縫合針 → ヒールゼリー）。1つ1つを「手順の段階」と呼ぶ。省略できる段階と、省略したときのダメージも持つ（例：切開のヒールゼリー）。特別機器のテーピングも1つの段階として書く（例：縫合針 → ヒールゼリー（省略可）→ テーピング。決定、2026-10-03） | [06_lesions.md](06_lesions.md) |
| 成功時の回復値 | 手順の段階ごと | - |
| 失敗時のダメージ値 | 手順の段階ごと（その段階の機器が失敗したとき）。無ければ医療機器データの既定値 | 2.4 |
| 失敗時の扱い | 最初に戻るか、戻らないか（戻るのは「失敗」のときだけ。決定、2026-10-03） | [06_lesions.md](06_lesions.md) 1章 |
| バイタル減少 | 病巣があるあいだの減少の間隔と量（病巣ごとに独立して処理する） | [03_game_rules.md](03_game_rules.md) 1.2 |
| 時間による変化 | 何秒後に、どう変わるか（例：裂傷の再出血。量の自然増で表す想定） | [06_lesions.md](06_lesions.md) 3.2 |
| 他の治療を妨げる状態 | 「無効」になる条件（例：血溜まり・膿が重なっている病巣は、ドレーン以外の操作がすべて無効。決定、2026-10-03） | [06_lesions.md](06_lesions.md) 1章 |
| 吸い出す量 | ドレーンで吸う血溜まり・膿の量、時間による自然増、最大値 | [05_instruments.md](05_instruments.md) 3.2 |
| 運び先 | ピンセットで動かす物の運び先（トレイ、または既定の位置と判定の範囲）。配置で上書きできる（決定、2026-10-03） | [05_instruments.md](05_instruments.md) 3.3 |
| 点数・評価の条件 | 病巣の点数（100点満点）の条件の値：出現から解消までの時間のしきい値、ミスが無い、手順の省略をしない、失敗・省略の減点、ヒールゼリーで覆いきらなかった分の減点（決定、2026-10-03）。**値は病巣ごとに個別に持ち**、試して調整する。時間のしきい値には難易度の係数が掛かる。点数から評価（Cool〜Bad）を決める | [03_game_rules.md](03_game_rules.md) 5.1 |

- 病巣は重なってよい（決定、2026-10-10。以前は「重ならない（血溜まり・膿と小さな切り傷だけ例外）」。[06_lesions.md](06_lesions.md) 1章）。重なった場所の操作は [05_instruments.md](05_instruments.md) 2.1。
- **メスの通過点のデータ作成のルール**（決定。試作 v02 の P40 への回答、2026-10-02。[05_instruments.md](05_instruments.md) 3.4）：判定データの通過点（`path`）をメスで切る段階に使う場合は、次を守って作る（データを読み込むときに自動でチェックするかは、テーマ9「本実装の計画」で決める）。
  - 隣り合う通過点は、メスの通過点の判定範囲の直径（例：判定範囲 2マスなら 4マス）より離す。
  - 隣の隣の通過点とは、判定範囲が重ならないようにする。
  - 曲がり角で、点を内側に寄せすぎない（近道したときに、次の点を通らずに次の次の点の判定範囲に入ってしまうのを防ぐ）。
  - これは**データ作成の制約**で、判定のロジック（目標以外の通過点の判定範囲に入ったら「飛ばした」＝失敗）は変えない。具体値は `TBD-05-11`。
- テーピング（特別機器）は、病巣データの治療手順の1段階として書く（`"instrument": "taping"`。値は医療機器データの「特別機器」の枠。3章）。
- 病巣の種類ごとの仕様は [06_lesions.md](06_lesions.md) 参照。
- **実行時に生成される病巣**：メスの空振りで発生する「小さな切り傷」（[06_lesions.md](06_lesions.md) 3.7）は、ステージデータに配置を書かず、操作の結果として生成される。病巣データ（種類）としては通常の種類と同じように持つが、判定データは切った軌跡から作る。**ステップの完了条件（全病巣完了）に含める**（治さないとステップを終えられない。06 3.7、決定）。

## 5. ステージデータ

### 5.1 構成

- ステップごとの配列で持つ。
  - 例：1ステップ目は切開（開腹）、2ステップ目は内臓、など。
- ステップ単位で、処理順の配列を管理する。
- **ステップのクリア条件**：病巣があるステップは「病巣が無くなったら次へ」（5.4）。病巣の無いステップ（例：注射を打つだけ。scenario.md のステージ1に「バイタル回復剤を打つ」場面がある）の進み方（決定、2026-10-03）：ステップごとに `clear_condition` を持ち、種類は「すべての病巣が完了」「回復剤を一定量注入」「指定の機器を一定回数使った」など。省略時は「すべての病巣が完了」。「すべての病巣」には、実行時に生成された小さな切り傷も含める（決定）。

### 5.2 ステージ全体で持つ値

| 項目 | 内容 |
|---|---|
| 開始時のバイタル | 0〜99 |
| 自然減少 | 間隔と量（病巣による減少とは独立して処理する） |
| 制限時間 | 秒数 |
| ゲームオーバーの会話 | ゲームオーバーのときに表示する会話を、原因（バイタル0・限度量の超過・時間切れ）ごとに持つ（決定、2026-10-03。[02_screens.md](02_screens.md) 2章） |
| ステージ係数 | 項目ごとの補正係数。指定しない項目は 1.0（[03_game_rules.md](03_game_rules.md) 6章） |
| 患者 | 患者ごとの薬剤別の限度量（医療機器データの既定値を上書きする。[05_instruments.md](05_instruments.md) 3.6）。1ステージに複数の患者がいる場合もある。患者の持ち方の詳細は `TBD-07-7` |
| 患者画像 | 手術エリアの背景に表示する患者の画像（呼吸・拍動のアニメーション用に最低3枚。[04_surgery_area.md](04_surgery_area.md) 3.2）。患者の持ち物の1つとして持つ。**ステップの間で差し替えられる**（例：患者A → 会話 → 患者B。会話を挟まなくてもよい。ステップごとに、そのステップで使う患者を指定する。決定、2026-10-03） |
| 開放条件 | ステージ選択で「開放済み」になる条件（例：前のステージをクリアした、あるフラグが立っている）。セーブデータの開放済みステージ（8章）と突き合わせる |
| クリア目標 | ブリーフィングに表示する文言と、判定の条件（既定：すべてのステップの完了） |
| 努力目標 | ブリーフィングに表示する文言と、達成の条件、達成したときのボーナス点（[03_game_rules.md](03_game_rules.md) 4・5章） |
| クリア後の処理 | クリアしたときに立てるフラグ、次に開放するステージ（シナリオ分岐。分岐の書き方は `TBD-07-5`） |
| コンティニューポイント | ステップの間に置く。通過するとセーブデータに到達点を保存する。リトライや、次に遊ぶときの開始位置に使う。状態はステージ開始時に戻す（決定、2026-10-03。[02_screens.md](02_screens.md) 3.3・3.5）。コンティニューポイントごとに、開始位置の選択に出す**表示名**（例：「2人目の治療から」）を持つ（決定、2026-10-10） |

- 「患者画像」「開放条件」「クリア目標」「努力目標」「クリア後の処理」は、ステージデータが持つ（決定、2026-10-03）。書き方の例は 5.8。

### 5.3 病巣の配置

処置データの中に、病巣の配置を並べる。

| 項目 | 内容 |
|---|---|
| 病巣の種類 | 病巣データ（4章）のどれを使うか |
| 位置 | 病巣を置くマス座標 [x, y]（病巣データの相対座標の原点） |
| 出現条件 | いつ出すか（開始時、○秒後、他の病巣の完了後など。`TBD-07-2`） |
| 上書き値 | この配置だけ変えたい値（2.4 の上書きの順番に従う。運び先を含む） |

### 5.4 処理順の例（会話 → 処置 → 会話）

```
ステップ
├── 会話データ（治療前の会話。指定したときだけ。キャラクター絵つきの会話）
├── 処置データ
│   ├── 病巣の配置1 を展開（種類・座標など）→ 治療（ゲーム操作）
│   ├── 病巣の配置2 を展開（種類・座標など）→ 治療（ゲーム操作）
│   ├── 処置中の会話データ（字幕）
│   └── 病巣が無くなったら次へ
└── 会話データ（治療後の会話）
```

- 病巣1と病巣2は同時に処理される。
- **会話の2つの方法**（決定、2026-10-03。[02_screens.md](02_screens.md) 3.4）：
  - **キャラクター絵つきの会話（治療を止める会話）**：ステップの間（ステップ開始時）だけに出す。最初のステップの治療前の会話は会話画面、途中のステップの治療前の会話はゲーム画面に重ねて出す。常にあるものではなく、ステップに会話データを書いたときだけ出す。出している間は時間・バイタルの減少・回復などをすべて止める。出すときは表示中の字幕を打ち切る。選択肢（フラグ）を出せる。
  - **字幕**：処置中の会話。治療操作と同期を取るのが難しいので流れっぱなしにする（進行を止めない）。
- **途中のステップの治療後の会話**も、止める会話（キャラクター絵つき）としてステップの間に出す。ステップの間の順番は「治療後の会話 → コンティニューポイント → 次のステップの治療前の会話」（決定、2026-10-10。[02_screens.md](02_screens.md) 3.5）。
- **指定の病巣が出たときに止める会話を出したい場合は、ステップを分ける**（例：ステップ1＝病巣Aの治療 → ステップ2の治療前の会話 → ステップ2＝病巣B）。ステップの途中で止める会話は出さない。
- 処置中の会話（字幕）で、医療機器を強調表示する指定はしない。強調表示は、出ている病巣の今の段階から自動で決まる（[05_instruments.md](05_instruments.md) 2.8）。
- ゲーム中のテキスト（処置中の会話・指示）はステージ側に持つ（[scenario.md](../scenario.md) の方針）。
- **scenario.md の旧仕様の文言についての注記**：scenario.md のゲーム内テキストには旧仕様の文言が含まれる（ステージ1の「掴んで画面外に出すんだ」は、新仕様ではトレイへ運ぶ。「最後にヒールゼリーで止血するぞ」は、新仕様の用途は癒着。裂傷の手順に「ピンセット」が出てこない点も spec/06 と異なる。「〇〇強調」の書き込みは、チュートリアル用の強調表示を廃止したため、医療機器の自動の強調表示（[05_instruments.md](05_instruments.md) 2.8）で置き換わる）。scenario.md はユーザーの原稿のため直さず、**ステージ1をステージデータにするときに、新仕様の文言へ書き換える**（書き換えの採否はユーザーが決める。試作 v02 の P56・P57）。

### 5.5 処置内容の分岐

- 会話の選択肢（フラグ）によって、同じステージの中で処置データを切り替えられるようにする。
  - 例：ステージ3では、選択肢によって処置の内容（病巣の構成・手順）が変わる。シナリオの結果は変わらない。
- ステージ選択時の難易度（係数による数値の補正、[03_game_rules.md](03_game_rules.md) 6.3）とは別の仕組み。
- 分岐の書き方（ステップ単位で切り替えるか、処置データ単位か）は `TBD-07-5`。

### 5.6 課題

- 上記の構成では処理が一本道（シングルスレッド）になっている。複数の病巣が同時多発する仕組み（イベントでの出現など）を考える必要がある（`TBD-07-9`）。病巣の出現条件の書き方は `TBD-07-2`。

| 自然減少のタイマー | 引き継ぐ（リセットしない） | 最初から（開始から計る） | 最初から（開始から計る） |

| 注射のゲージ | 引き継ぐ | 満タン | 満タン |
| 麻酔の残り時間 | 引き継ぐ | 0 | 0 |
| 患者ごとの薬の投与量の累計 | 引き継ぐ | 0 | 0 |
| 選択中の機器 | 引き継ぐ | ヒールゼリー | ヒールゼリー |

### 5.9 トレーニング用ステージ

- トレーニングモード（[02_screens.md](02_screens.md) 3.7、[03_game_rules.md](03_game_rules.md) 3.2）専用のステージを、**ステージデータの形**で持つ（決定、2026-10-03。通常のステージと仕組みをそろえるため）。
- このステージデータに持つもの：開始時のバイタル、自然減少、ステージ係数、患者（薬の限度量、背景の患者画像）など（5.2 と同じ項目）。
- **制限時間は持たない**（トレーニングモードには制限時間が無い）。
- **病巣の配置は書かない**。選んだ病巣（指定モード）、または治療したことのある病巣からランダムに選んだ病巣（ランダムモード）から、実行時に作る。ランダムモードの位置はランダム（はみ出さない範囲）。
- 指定モードで病巣を出す位置（手術エリアの中央）は、**このステージデータに書く**。通常の配置（5.3）と同じく、書いた位置を病巣データの相対座標の原点にする（特別な取り決めは持たない。決定、2026-10-10）。
- ランダムモードで出す病巣の数（例：5つ）の持ち方は `TBD-02-21`。

## 8. セーブデータ

- 自動セーブ。ブラウザのローカルストレージに保存する（[02_screens.md](02_screens.md) 4章）。
- 保存する内容：クリア状況（開放済みステージ）、ランク、フラグ、オプション設定、トレーニングモードの記録、**ステージごとの到達したコンティニューポイント**。
- **到達したコンティニューポイント**（決定、2026-10-03）：ステージごとに、どのコンティニューポイントまで進んだかを保存する。**難易度ごとには分けない**。保存の単位は「ゲーム前の会話で選んだ選択肢の組み合わせ」ごと（決定、2026-10-03。試作 v03 の P73 への回答）。ブリーフィングのあとの開始位置の選択に使う（[02_screens.md](02_screens.md) 3.3）。分岐（選択肢）ごとに、どこまで到達したかが分かるように持つ。コンティニューポイントより前に立てたフラグも一緒に保存する（決定、2026-10-03）。同じ単位で、ゲーム中に違う選択をして同じコンティニューポイントに着いたときは、最後に到達したときのフラグで上書きする（決定、2026-10-10）。
- **トレーニングモードの記録**（決定、2026-10-03）：
  - 治療したことのある病巣の**種類**。その病巣が出るステージを**クリアした時点**で記録する（記録の細部は `TBD-07-14`）。
  - ベスト記録：**病巣の種類 × 難易度ごとに、最高評価と最短時間**（決定、2026-10-03）。
- 形式と保存のタイミングは `TBD-07-4`。
