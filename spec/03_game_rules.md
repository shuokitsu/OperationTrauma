# 03 ゲームルール

- ステータス：草案
- 最終更新：2026-10-09

> **表記について**：数値は、決定した値と、例（決定ではない）を区別して書く。決定記録に無い規則を補うために推奨案を書いた箇所は **【仮案・未確認】** と明記し、対応する TBD を 7 章に置く。用語は [glossary.md](glossary.md) を参照（病巣、ステージデータ、病巣データ、医療機器データ、ストック、ゲージなど）。

## 1. バイタル

### 1.1 基本

| 項目 | 値 |
|---|---|
| 範囲 | 0〜99（単位：バイタル値） |
| 最大値 | 99 |
| 開始時の値 | ステージデータで指定する |
| ゲームオーバー | 0 になったとき |

### 1.2 増減

増減の量の単位はすべて「バイタル値」。

| 種類 | 内容 | 値 |
|---|---|---|
| 自然減少 | 一定時間ごとに下がる | 間隔と量を**ステージデータ**で指定する（例（決定ではない）：2秒ごとに1） |
| 病巣による減少 | 病巣があると一定時間ごとに下がる | 間隔と量を**病巣データ**で指定する（[06_lesions.md](06_lesions.md)） |
| 治療成功 | 手順の1段階が完了すると回復する | 病巣データに持つ（手順の段階ごと。[05_instruments.md](05_instruments.md) 2.1） |
| 失敗 | ダメージを受ける | 病巣データ（手順の段階ごと）の値。無ければ医療機器データの既定値（[07_data_format.md](07_data_format.md) 2.3） |
| 空振り | ダメージを受ける、または回復する、何も起きない（機器ごとに違う） | 医療機器データ（[05_instruments.md](05_instruments.md) 1.1） |
| ヒールゼリーを塗っている間の回復 | 塗っている間、成功・無効・空振りに関係なく回復する | 押した瞬間に1、以後2秒ごとに1、1回（ストック1回分）につき最大10（[05_instruments.md](05_instruments.md) 3.1） |
| 回復剤の注射 | 注入量に応じて回復する | 1回の最大注入で 20（仮の値。本家の値を調べる：`TBD-03-4`。「1回」の定義は [05_instruments.md](05_instruments.md) 3.6） |
| 薬の限度量の超過 | バイタルとは関係なくゲームオーバー | [05_instruments.md](05_instruments.md) 3.6、3章 |

- 「無効」の操作では、ダメージも回復も起きない（4分類は [07_data_format.md](07_data_format.md) 2.2）。無効のとき画面にメッセージは出さない（音は機器データ。[05_instruments.md](05_instruments.md) 3.1）。
- 自然減少と病巣による減少は、**それぞれ独立したタイマーで個別に（非同期で）判定・処理する**。
  - 例（決定ではない）：自然減少が「2秒ごとに1」、病巣Aが「3秒ごとに2」なら、2秒・3秒のそれぞれのタイミングで別々に減る。
  - 病巣が複数あれば、病巣ごとに別々のタイマーを持つ。治療が終わった病巣のタイマーは止まる。
- **タイマーの起点とリセット**（決定、2026-10-03）：
  - 各タイマーは、開始の時点（自然減少はステージ開始、病巣は出現の時点）から計り始め、**最初の減少は1間隔後**に起きる。
  - 自然減少のタイマーはステージ開始から連続して動き、ステップが変わってもリセットしない。
  - 一時停止で止まり、再開で続きから動く。
- 一時停止中は、ゲーム内の時間に関わるタイマーとアニメーションがすべて止まる（止める範囲は [02_screens.md](02_screens.md) 3.4）。
- 最大値（99）を超えて回復しない。

### 1.3 麻酔

- 麻酔が効いている間は、拍動テンポが遅くなるとともに、バイタルの減少も緩やかになる。
- 効果時間と「減少を緩やかにする度合い」は、医療機器データ（麻酔薬）に基本値を持ち、係数で補正する（6章）。
- **重ねがけできる**（残り時間に効果時間を足す）。そのかわり、患者ごとの限度量を超えて投与するとゲームオーバーになる（3章、[05_instruments.md](05_instruments.md) 3.6）。
- **緩やかにする対象と方法**（決定、2026-10-03）：自然減少と病巣による減少の**両方**を緩やかにする。実装は、減少の**間隔**を長くする（間隔 ＝ 基本の間隔 × **伸び倍率**。伸び倍率が 2.0 なら間隔は2倍）。値は「間隔を何倍に伸ばすか」で持ち、係数は「×」で掛ける（係数が大きいほど麻酔がよく効く。ほかの項目と向きをそろえるため。決定、2026-10-03）。失敗・空振りのダメージには効かない。
  - **理由**：間隔を変えれば、バイタルを整数のまま扱える（量に掛けると 0.5 のような端数が出る）。

| 項目 | 基本値の置き場所 | 基本値 |
|---|---|---|
| 効果時間 | 医療機器データ（麻酔薬） | 未定（例（決定ではない）：10秒。`TBD-03-6`） |
| 減少の間隔の伸び倍率 | 医療機器データ（麻酔薬） | 未定（例（決定ではない）：2.0＝間隔2倍。`TBD-03-6`） |

### 1.4 ゲージの色

- ここでの「ゲージ」はバイタルを表示するバイタルゲージ。注射のゲージ（薬の残量）とは別物（[glossary.md](glossary.md)）。

| バイタル | ゲージの色 | 拍動テンポ |
|---|---|---|
| 51〜99 | 緑 | 通常 |
| 26〜50 | 黄 | 早い |
| 1〜25 | 赤 | 危険域 |

- 麻酔が効いている間は、バイタルに関係なく拍動テンポが遅くなる。ゲージの色はバイタルに従う。
- テンポの表現は [04_surgery_area.md](04_surgery_area.md) 参照。

#### 心電図（決定、2026-10-09）

- バイタルゲージの後ろ（背景）に、**心電図の波形**を流して表示する。波形の拍は上の拍動テンポに合わせる。
- **バイタルが下がるほど、拍が早くなる。**
- **麻酔が効いている間は、バイタルに関係なく安静な（ゆっくりした）拍になる。**
- **薬を打ちすぎる（限度量を超える。麻酔の打ちすぎなど）と、心電図が平坦（ゼロ）になる**（ゲームオーバーの演出。[05_instruments.md](05_instruments.md) 3.6）。
- 心電図の拍に合わせて **SE を鳴らす**（[08_assets.md](08_assets.md)）。
- 細部（決定、2026-10-09）。テンポの具体値は `TBD-04-4`：
  - **テンポはバイタルに応じてなめらかに変える**（段階はゲージの色で分かるので、心電図は細かな変化を伝える役）。例（決定ではない）：99 で 1分に60拍 → 1 で 1分に150拍。値は試して調整する。上の表の「通常・早い・危険域」は、テンポの目安として残す。
  - **平坦にするのは、限度量の超過とバイタル0** のとき。時間切れでは平坦にしない（患者はまだ生きている。時間切れの会話で表す）。
  - 平坦になったら「ピー」と鳴り続け、ゲームオーバーの会話が始まったら数秒かけて小さくして消す。
  - メニュー（一時停止）中と、治療を止める会話の間は、波形の流れも拍の音も止める（ゲーム内の時間に関わるものはすべて止める。[02_screens.md](02_screens.md) 3.4）。
  - 音の大きさはオプションの SE 音量に従う。専用の設定は作らず、試作で鳴らしてうるさければ考え直す。
  - 麻酔の効き始め・切れたときは、数秒かけてなめらかにテンポを移す（急に切り替えない）。
  - 患者画像の拍動アニメーション（[04_surgery_area.md](04_surgery_area.md) 3.2）も、心電図と同じテンポで動かす。

## 2. 制限時間

- ゲーム画面の、医療機器の反対側の上端に残り時間を表示する（[02_screens.md](02_screens.md) 3.4）。
- 制限時間はステージデータで指定する（秒）。ステージ全体で1つ（ステップごとには分けない）。
- 時間切れになったら、会話を表示したのちゲームオーバーにする（ゲームオーバーは原因にかかわらず会話を挟む。3章）。

## 3. クリア・ゲームオーバー条件

| 結果 | 条件 |
|---|---|
| クリア | 目的（クリア目標）を達成する |
| ゲームオーバー | バイタルが 0 になる、制限時間が切れる、または薬の投与量が患者ごとの限度量を超える（[05_instruments.md](05_instruments.md) 3.6）。**どの原因でも、原因ごとの会話を表示してから**ゲームオーバー画面へ（決定、2026-10-03。[02_screens.md](02_screens.md) 2章） |

### 3.1 同時に成り立ったときの優先順位（決定、2026-10-03）

同じ瞬間に複数の条件が成り立ったときは、次の順で判定する。

1. バイタルが 0
2. 限度量の超過
3. 時間切れ
4. クリア（最後の病巣の治療が完了した）

- **同時に成り立つことがある理由**：ゲームは画面の更新（1秒に約60回）ごとに、時間を進める → 操作を処理する → バイタルを増減する → 終了条件を調べる、を繰り返す（イベントで即座にゲームオーバーにするのではなく、1回の更新の中でまとめて調べる）。1回の更新の間に、例えば「最後の病巣の治療が完了した」と「病巣による減少でバイタルが 0 になった」が両方起きると、同時に成り立つ。このときは上の順で1つに決める。
- ゲームオーバーの会話を表示している間は、ゲーム内の時間を止める。会話の途中でバイタルが 0 になる、といったことは起きない。会話が終わったら必ずゲームオーバーにする。

### 3.2 トレーニングモード

トレーニングモード（[02_screens.md](02_screens.md) 3.7）のルール（決定、2026-10-03）。

| 項目 | 内容 |
|---|---|
| バイタル | あり。減少・回復・ダメージは本番と同じように働く。開始時の値・自然減少・ステージ係数・患者（限度量など）は**トレーニング用ステージ**（ステージデータの形。[07_data_format.md](07_data_format.md) 5.9）に持つ |
| 制限時間 | なし |
| ゲームオーバー | あり（バイタルが 0、薬の限度量の超過）。ゲームオーバーになったら病巣選択画面に戻る（[02_screens.md](02_screens.md) 3.7） |
| 終わり | 出した病巣（ランダムモードは決めた数）の治療が終わったら、リザルトへ（[02_screens.md](02_screens.md) 3.7） |
| 難易度 | ステージと同じ難易度係数を使う。病巣選択画面で切り替える（6.3） |
| 点数・評価 | 病巣の評価はステージと同じ（5.1）。リザルトとベスト記録は [02_screens.md](02_screens.md) 3.7 |

## 4. 目標

| 種類 | 内容 |
|---|---|
| クリア目標 | ステージをクリアするための条件。ブリーフィングで表示する。ステージデータに持つ（[07_data_format.md](07_data_format.md) 5.2） |
| 努力目標 | ゲーム中に達成を目指す目標。ブリーフィングで表示し、達成すると高ランクになる（努力目標ごとのボーナス点。5章） |

## 5. 評価・ランク

- **病巣の点数を積み上げて、ステージの評価（ランク）を決める**（決定、2026-10-03）。ステージ全体の合計を100点にする形はやめた。
  - 病巣1つは内部的に **100点満点**で採点する（5.1）。
  - ステージの最大点 ＝ 100点 × 病巣の数 ＋ 努力目標のボーナス点の合計（例：病巣が5つで努力目標が無ければ最大500点）。
  - 最大点の**何割を取ったか**でランクを決める。
- ステージの評価と病巣の治療の評価（Cool〜Bad）は、この病巣の点数でつながる（共通化。`TBD-03-16` は決定）。
- コンティニューポイントから始めたときは点数が 0 からになり、コンティニューポイントより前の病巣は点が入らない（決定、2026-10-03。[02_screens.md](02_screens.md) 3.5）。そのため評価は低くなる。それらの病巣も最大点に数える（0 点として扱う。決定、2026-10-03）。数えるのは、コンティニューポイントより前のステップに配置された病巣すべて（出現条件にかかわらない。処置内容の分岐は今のフラグで決まるほう。小さな切り傷は数えない。決定、2026-10-03）。
- 最大点に数える病巣（決定、2026-10-03）：ステージデータに配置した病巣のうち、実際に出た病巣だけを数える（処置内容の分岐で数が変わっても、出た数で計算）。ただし、コンティニューポイントから始めたときの、それより前のステップの病巣は、上の箇条のとおり（出現条件にかかわらず数える）。メスの空振りで出る小さな切り傷は数えず、点も入らない（治療しないとステップは終わらない。[06_lesions.md](06_lesions.md) 3.6）。
- 努力目標（決定、2026-10-03）：努力目標ごとにボーナス点を持ち（値はステージデータ。例：1つ 50点）、最大点にも含める。
- 最大点が 0 のステージ（病巣も努力目標も無い）は、ランクを付けない。リザルトはクリアだけを表示する（決定、2026-10-03）。
- 点数は整数。

ランクの割合（決定、2026-10-03）。前の点数の表を、そのまま割合に読み替えたもの：

| ランク | 最大点に対する割合 |
|---|---|
| XS | 100％（満点） |
| S | 95％以上 |
| A | 80％以上 |
| B | 60％以上 |
| C | 40％以上 |
| D | 40％未満 |

- リトライした**回数**はランクに影響しない。ただし、コンティニューポイントから始めると点数が 0 からになるので、そのプレイのランクは低くなる（上の箇条、[02_screens.md](02_screens.md) 3.5）。

### 5.1 病巣の点数と治療の評価（Cool／Good／Fine／Bad）

- **病巣1つの治療が終わるごとに**、その病巣の評価を表示する（決定、2026-10-03）。
  - 途中の**手順の段階**が終わったときは「**OK**」と表示する。
  - 治療の完了時（最後の段階が終わったとき）に、評価（Cool／Good／Fine／Bad）を表示する。
- 評価の並び：**Cool ＞ Good ＞ Fine ＞ Bad**（決定）。
- 評価は、その病巣の点数（100点満点）から決める。
- 点数の条件（暫定、決定 2026-10-03）。しきい値などの値は**病巣データに持つ**（[07_data_format.md](07_data_format.md) 4章）。試しながら調整する。

| No | 条件 |
|---|---|
| 1 | 出現から解消（治療の完了）までの時間 |
| 2 | ミスが無い |
| 3 | 手順の省略をしない（例：切開の消毒＝ヒールゼリーを省略しない） |

- **失敗は減点**する（決定、2026-10-03）。
- 「**ミス**」は、その病巣への操作の「失敗」だけを数える。無効は数えない。空振りはどの病巣にも結び付かないので、病巣の点数には影響しない（ダメージは受ける）（決定、2026-10-03）。
- 点数の出し方（決定、2026-10-03。値は暫定）：3つの条件に配点し、失敗・省略で減点する。0点未満にはしない。
  - 基本の形（例）：時間 60点（早いほど多い）＋ ミスが無い 20点 ＋ 手順の省略をしない 20点。失敗1回ごとに 10点減点。
  - **配点・減点の値は病巣ごとに個別に持つ**（病巣データ）。実際に試して調整する。
  - ヒールゼリーで、しきい値（例：80%）以上覆って成功したが、すべては覆わなかった場合も減点する（例：80%で -20点。決定、2026-10-03。[05_instruments.md](05_instruments.md) 3.1）。
  - **難易度も影響する**：難しいほど早く処置しないと時間の点が取れない（時間のしきい値を係数で短くする。制限時間と同じく「基本値 × 係数」で、係数が小さい難易度ほど短くなる。6.2）。
- 点数と評価の対応（決定、2026-10-03）：Cool 90点以上／Good 70点以上／Fine 40点以上／Bad 40点未満。
- **評価を直接決める特別な処理は持たない**（決定、2026-10-03）。病巣ごとの配点・減点で表す。
  - 例：バッドテーピング（ヒールゼリーを省略してテーピングした。[05_instruments.md](05_instruments.md) 4章）は、その病巣の「省略の減点」を大きくする（例：マイナス65点）ことで Bad になるようにする。以前の「必ず Bad」の決まり（A23）はこれに置き換えた。
- 表示：病巣の近くに文字＋評価ごとの SE（決定。見た目はテーマ5。[02_screens.md](02_screens.md) 3.4）。
- 医療機器の強調表示は評価・点数に影響しない（決定）。

## 6. 係数による補正（ステージ補正・難易度）

### 6.1 考え方

- パラメータは**基本値**を1か所（医療機器データ、病巣データ、ステージデータ）に持ち、**係数**を掛けて実際の値を決める。
- 係数は2種類ある。

| 係数 | 置き場所 | 用途 | 初期値 |
|---|---|---|---|
| ステージ係数 | ステージデータ | そのステージ固有の補正（例：麻酔が効きにくい患者） | 1.0 |
| 難易度係数 | システムデータ（難易度） | プレイヤーが選んだ難易度による補正 | 1.0（標準の難易度） |

```
実際の値 ＝ 基本値 × ステージ係数 × 難易度係数
```

- 係数を指定しない項目は 1.0（補正なし）とする。
- 係数は、他の上書き（医療機器 → 病巣 → 配置。[07_data_format.md](07_data_format.md) 2.4）が済んだ**最後**に掛ける。
- **係数の向き**（決定、2026-10-03）：係数は「その項目の効きの強さ（量・割合・速さ）」に掛ける。係数が大きいほど、ダメージや減少は大きく／速く、回復や効果時間や制限時間は大きく／長く／速くなる。このため、**時間・間隔で表す項目のうち「速さ」として効くものは、掛け算ではなく割り算にする**。

  | 演算 | 該当する項目 |
  |---|---|
  | 基本値 × 係数 | 量・大きさ・長さ：ダメージ、減少の量、回復量、麻酔の効果時間、制限時間、開始時のバイタル、薬の限度量 |
  | 基本値 ÷ 係数 | 間隔・かかる時間（短いほど効きが強い）：自然減少の間隔、病巣による減少の間隔、ストックの回復時間、注射のゲージの回復時間 |

- **端数の扱い**（決定、2026-10-03。プレイヤーに有利なように**切り上げ**）：
  - バイタルは内部では小数のまま持つ。係数を掛けたダメージ・回復量も、1つずつ丸めずに小数のまま足し引きする（ダメージを切り上げるとプレイヤーに不利になるため、丸めるのは表示と判定だけにする）。
  - 表示・ゲージの色・バイタルを使う条件（努力目標など）は、小数点以下を**切り上げた**値で行う（例：内部 0.3 なら表示は 1）。
  - ゲームオーバーは、内部の値が **0 以下**になったとき（表示が 1 のうちはゲームオーバーにならない）。
  - 最大値 99 を超えない（切り上げた表示も 99 まで）。
  - 回数など整数で扱う値（ストック数など）は係数の対象外とする。
- **ヒールゼリーの回復の上限**（決定、2026-10-03）：塗っている間の回復は、1回あたりの回復量と上限（基本値 10）の**両方**に同じ係数を掛ける。

#### 計算の例（数値はすべて例で、決定値ではない）

| 項目 | 基本値 | ステージ係数 | 難易度（例） | 実際の値 |
|---|---|---|---|---|
| 自然減少の間隔 | 2秒ごとに1 | 1.0 | やさしい（減少の係数 0.7） | 2 ÷ (1.0 × 0.7) ＝ 約2.86秒ごとに1 |
| メスの失敗ダメージ | 2 | 1.0 | むずかしい（ダメージの係数 1.3） | 2 × 1.0 × 1.3 ＝ 2.6（内部は小数のまま引く。バイタルの表示は切り上げ） |
| 麻酔の効果時間 | 10秒（例） | 0.5（麻酔が効きにくい患者） | ふつう（1.0） | 10 × 0.5 × 1.0 ＝ 5秒 |

### 6.2 係数を掛けられる項目（決定、2026-10-03）

空間の大きさや回数など、掛けるとゲームの感覚が変わりすぎるものは「対象外」にする。開始時のバイタルと薬の限度量は対象にする（決定、2026-10-03）。

| 項目 | 基本値の置き場所 | 係数の対象 | 補足 |
|---|---|---|---|
| 麻酔の効果時間 | 医療機器データ | 対象（×） | 決定済み（効果時間は係数で補正する） |
| 麻酔の減少の間隔の伸び倍率 | 医療機器データ | 対象（×） | 係数が大きいほど麻酔がよく効く（決定、2026-10-03） |
| 自然減少（間隔） | ステージデータ | 対象（÷） | - |
| 自然減少（量） | ステージデータ | 対象外（間隔のほうに掛ける。二重に掛けない） | - |
| 病巣による減少（間隔） | 病巣データ | 対象（÷） | - |
| 病巣による減少（量） | 病巣データ | 対象外（間隔のほうに掛ける） | - |
| 失敗・空振りのダメージ | 医療機器データ、病巣データ | 対象（×） | - |
| 病巣の点数の時間のしきい値 | 病巣データ | 対象（×。制限時間と同じ向き） | 難易度が影響することは決定（2026-10-03。5.1）。6.3 の例では「回復・効果時間・制限時間」のグループの係数（むずかしい 0.7）で短くなる |
| 治療成功・注射の回復量 | 病巣データ、医療機器データ | 対象（×） | ヒールゼリーの塗り回復は上限にも掛ける（6.1） |
| ストックやゲージの回復時間 | 医療機器データ | 対象（÷） | ヒールゼリーのストック、注射のゲージ |
| 制限時間 | ステージデータ | 対象（×） | - |
| 開始時のバイタル | ステージデータ | 対象（×） | 99 を超えたら 99 にする（決定、2026-10-03） |
| 薬の限度量 | ステージデータ（患者） | 対象（×） | 決定、2026-10-03 |
| 判定範囲・猶予幅・筆の半径・運び先の範囲 | 医療機器データ、病巣データ | 対象外 | 空間の大きさ。端末や難易度で操作感を変えない（[05_instruments.md](05_instruments.md) 3.4 も対象外） |
| ストック数、ゲージの容量 | 医療機器データ | 対象外 | - |

### 6.3 難易度

- **難易度はステージを選ぶときに、ステージごとに選ぶ**（[02_screens.md](02_screens.md) 3.2）。順番は ステージ選択 → 難易度 → 会話・ブリーフィング（選択肢）→ 開始位置 → ゲーム（[02_screens.md](02_screens.md) 3.2・3.3）。オプションなどで一律に設定する方式にはしない。
- 難易度ごとの係数は、システムデータにまとめて持つ（[07_data_format.md](07_data_format.md) 6章）。実体は項目ごとの係数。下の表は、それを「ダメージ・減少」と「回復・効果時間・制限時間」の2グループにまとめて示した**例**。

| 難易度（名前も例） | 係数の例（ダメージ・減少） | 係数の例（回復・効果時間・制限時間） |
|---|---|---|
| やさしい（例） | 0.7 | 1.3 |
| ふつう（例） | 1.0 | 1.0 |
| むずかしい（例） | 1.3 | 0.7 |

- **この表の名前と数値はすべて例で、決定ではない**（`TBD-03-9`）。
- 難易度の段階数と名前は `TBD-03-9`。
- リトライしても難易度は変わらない。
- 難易度は、病巣の点数の時間のしきい値に影響する（5.1、決定）。それ以外に点数・ランクへ影響させるか、難易度ごとにランクを記録するかは `TBD-03-10`。
- シナリオ原稿のステージ3にある「手術難易度の分岐（結果は変わらない）」は、**この難易度とは別のもの**。会話の選択肢によって処置の内容が変わる分岐のこと（[01_overview.md](01_overview.md) 5.1、[07_data_format.md](07_data_format.md) 5.5）。
