## 1. データの種類（4種類）

値の性質ごとに、置き場所を4つに分ける案。

| データ | 何を表すか | 考え方 | 例 |
|---|---|---|---|
| 医療機器データ | 道具そのものの性能 | **どの病巣・どのステージでも同じ値**になるもの | ストック数、ヒットエリア、空振りしたときの結果 |
| 病巣データ（種類） | 病巣の「ひな形」 | **その種類の病巣なら、どこに出ても同じ**になるもの | 切り傷の治療手順、成功時の回復値 |
| ステージデータ | その手術の状況 | **その場面だけ**のもの | 開始時のバイタル、どの病巣を・どこに・いつ出すか |
| 難易度データ | 難しさの補正 | 係数だけを持つ | ダメージ係数 1.3 |

### 1.1 病巣を「種類」と「配置」に分ける

- 今の仕様では、病巣データが「出現位置」「病巣位置」を持つことになっている。
- これを次の2つに分けると、同じ病巣を何度も書かずに済む。

| | 置き場所 | 持つもの |
|---|---|---|
| 病巣の**種類** | 病巣データ | 見た目、判定データの形、治療手順、回復値・ダメージ値、時間による変化 |
| 病巣の**配置** | ステージデータ | どの種類を・どこに（マス座標）・いつ出すか（出現条件）、この配置だけの上書き値 |

```
病巣データ（種類）        ステージデータ（配置）
┌──────────┐      ┌────────────────────┐
│ 切り傷           │ ←── │ 切り傷を [20,10] に、開始時に出す │
│  手順：ゼリー     │ ←── │ 切り傷を [60,30] に、10秒後に出す │
│  回復：3         │      └────────────────────┘
└──────────┘
```

| ID | 案 | 回答・決定 | 反映先 |
|---|---|---|---|
| R1 | データを4種類（医療機器／病巣（種類）／ステージ／難易度）に分ける | ✅ 変更して採用。難易度データは**システムデータ**とする（難易度以外にも調整用の値が出てくる可能性があるため）。項目が多くなれば専用ファイルに分ける。ほかの3つは案のとおり | spec/07 2.1・6章、03 6章、08 1章、glossary |
| R2 | 病巣を「種類」（病巣データ）と「配置」（ステージデータ）に分ける | ✅ 採用 | spec/07 2.1・4章・5.3、glossary |

## 2. 操作の結果の分類（共通の言葉）

D2 の食い違いは、「どんな場面の結果なのか」が混ざっていることが原因と考えられる。まず結果を4つに分けて名前を付ける案。

| 結果 | 意味 | 例 |
|---|---|---|
| 成功 | 治療手順の1段階が完了した | 通過点をすべて通ってメスで切開できた |
| 失敗（NG） | 病巣に対して操作したが、やり方を誤った | メスが猶予幅を外れた、ピンセットで運ぶ途中に落とした、手順と違う機器を使った |
| 無効 | 操作したが何も起きない（ダメージも無い） | 長い傷をヒールゼリーで覆いきれなかった、血溜まりがあってゼリーが効かない |
| 空振り | 病巣の無い場所を操作した | 何も無い皮膚をメスで切った |

| ID | 案 | 回答・決定 | 反映先 |
|---|---|---|---|
| R3 | 操作の結果を「成功／失敗／無効／空振り」の4つに分けて扱う | ✅ 採用 | spec/07 2.2、glossary |

## 3. 結果ごとの置き場所

### 3.1 基本ルール

| 結果 | 値の置き場所 | 理由 |
|---|---|---|
| 空振り | **医療機器データ** | 病巣が無い場所なので、道具の性質で決まる |
| 成功 | **病巣データ** | どれだけ回復するかは病巣によって違う |
| 失敗 | **病巣データ**（無ければ医療機器データの既定値） | 病巣ごとに重さが違う。ただし毎回書くのは大変なので、機器の既定値を使えるようにする |
| 無効 | 値は持たない | 何も起きないため |

### 3.2 上書きの順番

同じ値が複数の場所にあるときは、**より具体的なほうを優先**する。

```
医療機器データの既定値
   ↓ 病巣データに指定があれば上書き
病巣データ（種類）の値
   ↓ ステージの配置に指定があれば上書き
配置ごとの値
   ↓ 最後に係数を掛ける（03_game_rules.md 6章）
実際の値 ＝ 上の値 × ステージ係数 × 難易度係数
```

- 例：メスの失敗ダメージ
  - 医療機器データ（メス）の既定値：2
  - 病巣データ（切開）に指定が無ければ 2 を使う
  - 病巣データ（腫瘍の切除）で 4 と指定すれば、腫瘍のときだけ 4 になる

| ID | 案 | 回答・決定 | 反映先 |
|---|---|---|---|
| R4 | 空振りは医療機器データ、成功は病巣データ、失敗は病巣データ（無ければ医療機器の既定値）に持つ | ✅ 採用 | spec/07 2.3、05 2章 |
| R5 | 「医療機器 → 病巣（種類）→ 配置」の順に上書きし、最後に係数を掛ける | ✅ 採用 | spec/07 2.4 |

## 4. 今の仕様にある値の振り分け案

今の仕様書に出てくる値を、上のルールで振り分けた案。

### 4.1 医療機器データ

| 値 | 今の仕様（出典） | 補足 |
|---|---|---|
| ヒールゼリーのストック数・回復時間 | 5回、3秒で1回分（05 3.1） | - |
| 注射のゲージ回復時間 | 10秒（05 3.6） | - |
| 薬ごとの効果（回復剤の回復量、麻酔の効果時間・緩和率） | 最大 20 回復など（05 3.6、03 1.3） | 薬ごとに値を持つ |
| ヒットエリアの大きさ | 注射は 3×3（04 2章） | - |
| なぞり操作の判定範囲・猶予幅 | メスの案：2マス・3マス（05 3.4） | 病巣ごとに上書きできるようにするかは R6 |
| 空振りの結果 | ヒールゼリー：回復1、メス：ダメージ2＋裂傷の発生（05） | 結果の種類（ダメージ／回復／病巣の発生／なし）と値 |
| 失敗の既定値 | メス：2、縫合針：1（05） | 病巣データで上書きできる |

### 4.2 病巣データ（種類）

| 値 | 今の仕様（出典） | 補足 |
|---|---|---|
| 見た目 | 画像（04 2章） | - |
| 判定データの形 | 切開は通過点の案（06 3.5） | 形そのもの。置く位置は配置で決める |
| 治療手順 | 例：ドレーン → ピンセット → 縫合針 → ヒールゼリー（06） | 省略できる段階と、省略したときのダメージも持つ（切開のヒールゼリー） |
| 手順ごとの成功時の回復値 | （06 1章） | - |
| 手順ごとの失敗時のダメージ値 | （06 1章） | 無ければ医療機器の既定値 |
| 失敗時に最初に戻るか | （06 1章） | - |
| 病巣があるあいだのバイタル減少 | 間隔と量（03 1.2） | - |
| 時間による変化 | 裂傷の再出血（06 3.2） | 何秒後に、どう変わるか |
| 他の治療を妨げる状態 | 血溜まり・膿があるとヒールゼリーが効かない（06 1章） | 「無効」になる条件 |

### 4.3 ステージデータ

### 4.4 難易度データ

|---|---|
| 難易度ごとの係数 | 03 6.3 |
