# 試作を作るときに引き継ぐこと

- 試作（`_prototype_vNN/`）はコードを流用せずに `spec/` から作り直すため、仕様書に書かない「試作ならではの機能・作り方」をここに残す。**次の試作を作るときは、この一覧をすべて入れる**（2026-10-03 ユーザー指示）。
- 新しく「次の試作でも欲しい」と言われたものは、ここに足す。

## 作り方

| 項目 | 内容 | 初出 |
|---|---|---|
| GitHub Pages で動く形 | データ・画像・音はすべて相対パスで読み込む。リポジトリのルートの `.nojekyll` で `_` 始まりのフォルダも公開される。URL は `https://shuokitsu.github.io/OperationTrauma/_prototype_vNN/` | v03 |
| オプション画面 | 試作 v02 と同じ形（タイトル画面の上にパネルを重ね、項目ごとに値のボタンを並べる）。パネルは画面からはみ出さないこと（[bug_list.md](bug_list.md) の B1・B2） | v02（v03 で見切れを修正） |
| 素材の先読み | 仕様はステージごとの読み込み（spec/08 3.3）。試作では簡単のため、起動時に、データに出てくる画像をすべて読み込み、展開（decode）まで済ませてからタイトルを出す（読み込み中は件数を表示）。展開は画面が非表示だと終わらないことがあるので、時間で打ち切る（[bug_list.md](bug_list.md) の B4） | v03 |
| 動作確認 | ブラウザのプレビューが非表示だと画面の更新（requestAnimationFrame）が止まるので、確認用のスクリプトから `update` を直接回して確かめる。ブラウザが古いスクリプトを使い回すことがあるので、ファイルを変えたら `fetch(…, {cache:'reload'})` で読み直してから再読み込みする | v03 |
| 不具合の確認 | [bug_list.md](bug_list.md) の項目が再発していないか確かめる | v03 |
